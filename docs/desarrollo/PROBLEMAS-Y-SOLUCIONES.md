# Registro de problemas y soluciones

Este documento recoge problemas técnicos encontrados durante el desarrollo y cómo se investigaron y resolvieron. Debe completarse a partir de incidencias, commits, pruebas o recuerdos que puedan contrastarse. No inventar problemas ni fechas para que el proceso parezca más completo.

## Cómo registrar un problema

Para cada incidencia relevante, anotar:

1. **Síntoma:** qué veía el usuario o qué fallaba.
2. **Contexto:** qué parte de la aplicación estaba implicada.
3. **Investigación:** qué hipótesis se comprobaron y con qué herramientas.
4. **Causa:** causa confirmada o, si no se conoce, hipótesis pendiente.
5. **Solución:** cambio realizado y motivo.
6. **Validación:** prueba concreta que demuestra que se corrigió.
7. **Evidencia:** commit, pull request, issue, test o captura sin datos sensibles.

## Criterios

- Diferenciar causa confirmada de hipótesis.
- No incluir tokens, contraseñas, correos privados ni datos de usuarios.
- No afirmar que un problema está resuelto sin una comprobación.
- Si la solución fue propuesta por IA, indicarlo en la ficha.
- Registrar también los problemas que siguen abiertos.
